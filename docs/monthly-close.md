# 月度關帳 (Monthly Close)

本文件描述關帳工作流的設計目標與行為契約：期間狀態、步驟模型、每個步驟的資料建立
邊界，以及關帳完成條件。實作入口在 `src/application/monthly_close/` 與
`src/ui/features/monthly_close/`；決策理由見 ADR-0050、ADR-0052、ADR-0066、ADR-0070、
ADR-0072、ADR-0073、ADR-0080。

詞彙見 [`CONTEXT.md`](../CONTEXT.md)。本文件同時擁有**單一步驟的呈現決定**；跨頁可
複用的視覺契約屬 [`ui/visual-standards.md`](ui/visual-standards.md)，token 與元件表面屬
[`ui/design-system.md`](ui/design-system.md)。

## 1. 入口

關帳有兩條路由：選擇期間（輸入 `YYYY-MM`、按開始關帳後寫入期間狀態並進入工作區），
以及該期間的工作區。URL 有效等於該期間已有狀態紀錄；形狀不合法或尚未開始一律回選擇
頁，讀取失敗則顯示錯誤而不是回覆原路徑。切換期間不殘留前一期間的已載入值、草稿與
步驟檢視。

選擇頁以**最近六個月**的矩陣為預設入口：一格一個月，帶該月狀態（已關帳／進行中／未開
始／待審閱），點一格即選取，下方 `YYYY-MM` 選擇器仍可到達矩陣以外的任何月份。沒有期間紀錄的
月份一樣可選——選它正是建立紀錄的方式。狀態詞彙只在 `PERIOD_STATUS_TEXT` 一處；讀取失敗時矩
陣仍可點，只是狀態一律當未開始，並在上方以一行 caption 說明。

**預選期間**：選擇頁第一次載入時自動選取矩陣中最新的**已有紀錄**月份，而不是今天——使用者
回來的目的是續做未完的期間，落在無紀錄的當月等於每次都要重選。自動選取只發生一次，之後
使用者手動點選不被覆寫。

工作區 header 另備一個「切換期間」連結（指回選擇頁）：手機殼的 nav 是圖示化的，工作區內
直接給一條文字路徑，比讓使用者自己找圖示短。

當月還款集中到關帳的債務還款步驟，交易表單不再提供獨立還款入口。

## 2. 期間狀態

期間狀態是**唯一持久化的關帳工作流狀態**，只描述進度，不複製任何快照資料。

- 沒有狀態紀錄代表尚未開始關帳，不代表期間不存在。狀態在開始關帳時誕生。
- `NEEDS_REVIEW` 是待確認的暫停，唯一來源是前期被重開造成的連鎖降級。
- `CLOSED` 的期間以唯讀模式呈現，只有重開能解除。
- 就緒判定是衍生的，只檢查四類快照是否齊全；它與工作流狀態並存、不取代。

**暫停即強制順序恢復**：暫停期間瀏覽自由，但確認只能作用在行走位置——順序中第一個
未完成的步驟；對其他步驟確認會被拒絕。連鎖降級的期間維持暫停直到重新關帳。

**重開**：已關帳期間可經確認視窗重開，狀態回到進行中，報表與關帳步驟重設；其他已完成
步驟保留。連鎖降級期間走同一條路徑，但重開後八個步驟全部重設，恢復是完整的順序行走。

**連鎖降級**：重開某期間時，其後所有已關帳期間自動降為待確認，因為它們的定案可能基於
修正前的歷史。進行中與尚未開始的期間不受影響；被降級的期間不會自動回復，必須逐期
手動重開。

現金差異維持報表層級的警告，不暫停工作流。

## 3. 步驟模型

八個步驟依序為：帳戶餘額、證券買入／賣出、Portfolio 金流、專案結算、債務還款、
就緒檢查、財務報表、正式關帳。前六個步驟名用中文，後兩個也一併中文化；`Portfolio`
是保留的專有名詞。

- 每個步驟由**使用者確認**完成；系統的檢查結果只是證據。
- 確認等於冪等執行該步驟的資料建立（已存在則不重複）加上標記完成。輸入隨確認一次
  提交，沒有跨步驟的一鍵快照。
- 可重確認的步驟重複確認走同鍵幂等覆蓋，不產生重複文件。
- 證券買入／賣出允許空確認，系統不阻擋，空步驟在表單上方以單行 caption 說明「確認後仍會完成這個步驟」——不再彈確認框重述同一句話。空步驟只換掉表格本身，確認鈕與動作列留在原位，空狀態面板不佔滿整個步驟。
- 專案結算是無輸入的唯讀步驟：列出結算狀態與即時預覽，確認即建立專案快照。
- 就緒檢查只呈現就緒狀態與例外清單，**不呈現任何財務數字**；例外項目附
  跳轉導回修正，交易驗證問題沒有落點、只列文字。
- 財務報表必須先預覽再確認產生；就緒未成立時產生鈕停用，寫入路徑再檢查一次。
  報表畫面永遠顯示即時重算的預覽，已產生報表只當狀態旗標與比對基準；已關帳期間回看
  時才改顯示已產生報表。任一類別在當月沒有啟用中資料時視為通過，不單獨阻擋。
- 正式關帳呈現關帳活動與財務結果，經確認對話框正式關帳；確認框標題帶受影響的期間，
  關帳後總結固定為唯讀定案紀錄。正式關帳鈕用 `destructive` 變體（不可逆），鈕旁常駐
  一行鎖定說明；確認框只補受影響範圍，不重述畫面上已有的後果。

硬性條件只有三條：正式關帳需要其餘七個步驟皆已確認、財務報表已確認且
三張報表已產生、帳戶餘額不可空確認。其餘順序在非暫停期間只是 UI 引導。

暫停期間的步驟跳轉是重設語意：先確認，該步驟（含）之後全部重設，前期完成步驟保留。

### 報表漂移把關

財務報表的任一漂移都讓關帳鈕停用，並在該處提供回到財務報表的
捷徑；漂移期間財務報表提供重新產生。警示只表達有漂移、不報項數——任何計數
都對不上使用者看到的警示。判定涵蓋推導值與畫面未繪製的項，也不依賴關帳頁的聚合數字。

重新產生一律由使用者點擊觸發，不會有隱藏的靜默重算。

### 步驟 UI 的組構原則

- **單一 registry 是唯一列出八個步驟、也是唯一跨步驟讀取的地方**。新增步驟等於一個
  step hook 加一個 registry 條目。
- **每個步驟自行渲染自己要給使用者看的內容**：沒有獨立的證據通道，也沒有跨步驟共用
  的證據元件，因此不會出現同一份資料在別處被重畫的第二條呈現路徑。
- **每個步驟自載自己的資料**，失敗時顯示自己的罐頭錯誤。載入失敗代表資料未知，不是
  空。把關一律讀「已知且未失敗」；prefill 失敗不阻擋確認。
- 報表資料與持久化旗標由同一個步驟擁有，三者出自同一次載入，不會先後落地而互相矛盾。
- 刷新只有一個入口，由工作區統一觸發；呼叫點不需要知道哪個步驟擁有哪份資料。
- **表格型步驟只彈一次確認框**：空白步驟用 caption 說明，不另外擋在確認鈕前面（見 §3）。
- **步驟標題與內容之間拉一階間距**（前言 `pt-4`），標題才讀起來是標題而不是堆疊的第一塊。
- **步驟內的 tabs 在手機也是 tabs**：只有選中的面板顯示，分頁列自己橫向捲動。三張報表一次全部堆疊會讓手機永遠停在第一張。

### 載入時機

工作區在期間確定存在後才掛載，掛載即讓八個步驟同時各自載入。停留在選擇畫面時不發出
任何關帳讀取。扇出隨帳戶與專案數線性且有界；延遲面不構成瓶頸，因此不為載入型步驟
再加行走位置閘門。

量測時不要拿 DevTools 的 HTTP 請求數當讀取數（SDK 會 multiplex 與重送），也不要在開著
`StrictMode` 的 dev 環境量 production 成本。

## 4. 各步驟的資料邊界

| 步驟           | 確認時建立什麼                                           |
| -------------- | -------------------------------------------------------- |
| 帳戶餘額       | 只為有輸入的帳戶建快照；不為未輸入的帳戶偽造零值         |
| 證券買入／賣出 | 只提交新增或編輯的列；既有列以 id 更新、移除列以 id 刪除 |
| Portfolio 金流 | 為每個啟用中 portfolio 同鍵覆蓋當月快照                  |
| 專案結算       | 建立專案快照                                             |
| 債務還款       | 逐筆走付款的原子邊界；為無還款的貸款補零還款快照         |
| 就緒檢查       | 不建立資料，只讀                                         |
| 財務報表       | 同鍵覆寫三張報表，顯示標籤隨報表凍結                     |
| 正式關帳       | 把期間標記為已關帳                                       |

邊界由單一入口依步驟分派；共用流程只保留權限、狀態轉移與連鎖。終局步驟只把關、
就緒檢查以顯式的「無資料」表示，不靠處理缺席推斷。

每個步驟的輸入、預填與計算語意都必須呼叫與寫入路徑相同的 domain 計算，不在 UI 自建
第二條計算路徑。

## 5. 帳戶餘額步驟

依帳戶類型分區，所有必要輸入直接在頁面內。本步驟不可空確認：零輸入不產生任何快照，
就緒必然不成立。

現金與銀行輸入期末餘額；外幣另有金額與匯率，台幣價值由系統計算；證券以持倉表輸入，
可匯入上月持倉。重新進入已開啟的期間時，期末餘額由當月快照預填，使用者已輸入的值不被
覆蓋。

台幣金額一律是折合後的數字。會計 schema 不因這些輸入改變。
