# 報表層對明細科目採父科目 roll-up 與凍結標籤解析

**狀態：** 已接受
**規範來源：** [financial_report.md](../financial_report.md) §1、§2

明細科目（`type:category:detail`）不各自在報表上獨立成列，改為父科目 `type:category` 成列並加總金額，明細科目巢狀為其 `subItems`。理由是報表閱讀者先看類別總額、需要時再展開來源；獨立成列會讓使用者自建的明細科目把報表撐成不可掃描的長表。權益項不採同一條規則，直接呈現系統定義的五組。

標籤解析在**產生報表時凍結**進 persisted label：靜態科目目錄先解析，家庭自建科目覆蓋；明細標籤退回原始明細段（碼去掉父前綴），巢狀顯示組成「父標籤 › 明細標籤」。取捨是報表產生後改科目名稱不會回溯更新歷史報表——歷史報表是當時的觀察視圖，這是有意的。

## Considered Options

- 每個明細科目獨立成列：否決，使用者自建科目會讓報表失去可掃描性。
- 顯示時即時解析標籤：否決，讀取端每個消費者都要重建解析器，且改名會追溯改寫歷史報表。
- 權益五組也套 roll-up：否決，權益組別是系統定義的固定語意（期初、本期淨利、資本、股票報酬、調整），不是使用者分類。

## Revisit When

明細科目需要第三層（`type:category:detail:sub-detail`）時，roll-up 與標籤組成規則需要重新設計。
