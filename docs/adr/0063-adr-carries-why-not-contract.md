# ADR 只承載「為什麼」：規範細節歸主題文件

**日期：** 2026-09-24
**狀態：** 已接受
**規範來源：** `docs/development-guide.md` §3（文件分工、ADR 判準、先加後刪）

本 repo 的 ADR 只回答「當初為什麼這樣決定」。規範細節（欄位清單、enum 全集、公式、數值、驗收清單、class 名）住在該事實歸屬的主題文件，ADR 只留一行 `規範來源` 指標。

判準是一句話：**拿掉這個值，這句話還講得通嗎？** 講得通，它是列舉細節，歸主題文件；講不通，它是這個決定的一部分，留在 ADR。

## Considered Options

- **維持 ADR 兼載契約，主題文件一律改成指標。** 拒絕：多數契約變動（列高、頁寬）不需要重新權衡，卻會因此被迫開新 ADR，產生大量無實質取捨的決策紀錄；而改一行數值就得走開 ADR 的流程，實際上會繞過它。
- **ADR 完全不含任何數值。** 拒絕：拿掉數值後，「為什麼選這個」會退化成不可證偽的抽象敘述，讀者無法判斷這個決定到底決定了什麼。
- **為 UI 與架構詞彙另開 glossary 檔。** 拒絕：agent 的閱讀路徑已經指向 `docs/ui/ui-layer-architecture.md`，多一個 glossary 檔只是多一次可能漏讀的跳轉。

## Consequences

- 62 篇 ADR 中 57 篇含規範內容；其中 14 篇的內容同時存在於主題文件，需要收斂成單一來源。
- 5 份主題文件目前寫「以 ADR-x 為準」，在新模型下 ADR 不含規則，這些指標必須反向。
- 6 條事實目前沒有任何主題文件承接；依**先加後刪**，必須先替它們找到家，才能從 ADR 拆掉。
