# RWD 斷點契約:單一 md 斷點與分級導航殼

## 狀態

已接受(2026-09)

## 背景與動機

#85 前的版面沒有明文的響應式契約:行動版與桌機共用同一組導航(桌機 sidebar 縮窄
或依賴瀏覽器縮放)、Vite 樣板的 `#root { max-width: 1280px }` 殘留樣式與實際的全寬
版面矛盾,斷點語意散落在各元件的 class 裡,無人能回答「768px 屬於手機還是桌機」。

實作 #86 與 #87 時收斂出可驗證的行為,本 ADR 將其定為契約,作為後續任何版面變更
的比對基準。

## 決策

1. **單一斷點切換**:`md`(768px)是行動殼與桌面殼的唯一切換點,`lg`(1024px)僅
   用於桌面殼內的尺寸微調(側欄 224px → 256px)。禁止引入第二組「平板專用殼」。
2. **平板沿用桌面殼**:768px-1023px 呈現桌面版配置(固定側欄 + 內容補償 padding
   ),側欄收窄為 224px 使直式 iPad 可用內容寬度達約 512px;1024px 起恢復 256px,
   桌機視覺零變化。不為平板另做漢堡選單或摺疊側欄。
3. **行動導航 4+1 分組**:`< md` 只顯示 4 個主要目的地(Dashboard、Projects、
   Accounts、Reports)加一個 More 按鈕;其餘目的地進 bottom sheet。目的地清單
   以 `navigation.ts` 的單一 `NAV_ITEMS` 為來源,以 `group` 欄位分組,移動與桌
   面共用。
4. **表格橫向捲動政策**:寬表格(如退休年度明細)在手機以 `overflow-x-auto` 容器
   橫向捲動,不折行擠壓、不在手機砍欄位;卡片式列表(如交易列表)在所有斷點全寬
   度呈現。新元件擇一:資料密度優先 → 表格 + 橫向捲動;掃描效率優先 → 卡片。

## 影響

- 版面寬度只有三個合法值:行動(< 768)全寬、平板(768-1023)側欄 224px、
  桌面(≥ 1024)側欄 256px;對應驗收清單見
  [UI 架構文件](../ui-layer-architecture.md)的「RWD 斷點契約」章節。
- `App.css`(Vite 樣板殘留,`#root max-width: 1280px`)與本契約矛盾,已刪除。
- 已知偏差:交易列表的日期篩選列在 768px 溢位約 124px(`md:w-56` x2 無換行),
  屬待修缺陷,不影響本契約的其餘行為;修正時不得改變契約本身。
