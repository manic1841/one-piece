## Context

為什麼需要這個決策。寫出當下的既有事實與約束：實際程式碼現況、已存在的契約、量測數字。
不要寫成需求描述——未來讀者要知道「當時的世界長什麼樣」，才知道決策為何成立。

## Decision

決策本身，以及**為何選它**。若有不只一個方案，列出被否決的方案與否決理由；這是 ADR 最有價值的部分。

規範性細節（表格、可觸碰清單、API 契約）不寫在這裡。ADR 只記錄決策與取捨，規則住在對應的永久文件，
兩者不得重複同一事實。

## 影響

- 被改動的檔案與契約（列路徑）。
- 需要後續處理的債務、例外或未定案項目。
