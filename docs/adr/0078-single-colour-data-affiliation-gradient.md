# 圖表允許單色資料歸屬漸層，仍禁止裝飾性漸層

**日期：** 2026-10-06
**狀態：** 已接受
**規範來源：** [design-system.md](../ui/design-system.md) §1、[development-guide.md](../development-guide.md) §8、[visual-standards.md](../ui/visual-standards.md) 反模式 checklist

原本三處明文禁止圖表使用漸層，理由是漸層會掩蓋資料、把圖表變成裝飾。退休現金流投影圖需要以「面積帶」分辨收入與投資報酬兩條堆疊序列，而單色由線往基線淡出的填充（貼線 `0.38` → 基線 `0`）不是裝飾：它讓面積的**歸屬**（這片屬於哪條線）可讀，且淡出方向正好遠離讀者視線焦點。因此把禁令收窄為「**禁止裝飾性漸層**」，允許「單色、由序列自身顏色淡出、且有基線」的資料歸屬漸層；裝飾性漸層（多色、斜向、與序列無關的裝飾）仍禁止。

## Considered Options

- 維持禁令、改用平面半透明填充：否決——兩條堆疊帶重疊時平面填充會互相蓋色，交界處顏色混濁，反而更難辨識歸屬。
- 用不同純色的平面填充、靠色相區分：否決——序列已有 5 條，色相數量不足以再撐一組對比，且與「圖表保持安靜」的既有原則衝突。

## Consequences

- 「裝飾性」成為需要判斷的形容詞，而非可直接掃描的規則；判準落在漸層是否為**單色、源自序列自身顏色、且有基線**。
- 漸層需要 `<linearGradient>` 定義，因此幾何/繪製層多一個 id 命名空間，必須以元件實例為界避免多圖共用（`React.useId`）。
- 面積位於零基準下方時（支出），漸層方向須相對翻轉，否則濃度會落在基線而非線側；此翻轉屬實作契約，寫入 [component-catalog.md](../ui/component-catalog.md) 的 `ComposedChart` 條目。

## Revisit When

圖表開始出現多色或斜向漸層，或漸層被用在沒有基線的場合（例如散佈圖、雷達圖）時，重新檢視此例外是否被濫用。
