# 金額一律由「來源 + Method」推導，取消平坦金額與依賴圖

**日期：** 2026-10-20
**狀態：** 已接受
**規範來源：** [retirement-system.md](../retirement-system.md) §4

v1 用平坦金額描述收支（收入存 `currentAnnual` 與 `retirementAnnual`、支出存目前年支出與退休乘數），成長率散落在各列、由引擎各自解讀。重設計讓每一筆逐年金額都是一條投影規則：規則指向一個來源（科目、另一條規則或債務帳戶），再用 Method 說明怎麼算（跟隨通膨、指定成長率、取他條規則比例、固定金額、由債務攤還）。來源只提供數字，不決定金額方向，所以債務還款是一條支出規則而不是第三種方向；沒有來源、金額全由使用者輸入的則寫成人生事件。

理由是同一個事實只能有一條推導路徑。平坦金額讓「這筆錢怎麼變成明年的金額」同時存在於欄位值與引擎分支裡，改一個成長率要動兩處；改成規則後，成長只由 Method 表達，引擎只認已解析的數字。

## Considered Options

**沿用平坦金額與依賴圖。** 依賴圖已經能表達「支出是收入的百分比」，改動面也小。否決的原因是它只覆蓋百分比一種關係，通膨、成長率、債務攤還仍各自是欄位加引擎分支，等於保留兩套並行的推導方式。

## Consequences

- 舊的 `year` + `amount` 事件相容路徑移除，事件一律是多段 Phase。
- 規則的存在性與參照環在 schema 驗證期就擋下，不在引擎期才炸。
