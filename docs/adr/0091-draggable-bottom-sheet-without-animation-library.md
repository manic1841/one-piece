# bottom sheet 自寫拖曳手勢，不引入動畫函式庫

**日期：** 2026-11-06
**狀態：** 已接受
**規範來源：** [motion-system.md](../ui/motion-system.md) §5.3

bottom sheet 要跟手拖曳與阻尼歸位，而本專案至今沒有任何動畫函式庫，也只有觸發式動畫。我們自寫 pointer 手勢（約百行、零依賴），並讓所有 `side="bottom"` 的 sheet 預設可拖、由呼叫端的關閉函式承擔 dirty 的語意。

考慮過 framer-motion（成熟的 `drag`／`dragConstraints`），但它的價值集中在這裡用不到的宣告式編排；dnd-kit 已在依賴裡，卻是為排序而生，套到 sheet 會多一層對不上語意的抽象。自寫的代價是手勢邊界要自己顧（多指、flick、與內容捲動衝突），因此拖曳區限縮在 handle 帶，內容捲動不受手勢仲裁。

把手勢與 dirty 分開，是因為「怎麼關」與「關不關得成」是兩件事：元件只提供手勢，保護留在呼叫端，新增 sheet 就不必再想一次互動規則。

## 被否決的方案

- **framer-motion**：換來一個 runtime 依賴與一套新語彙，只為一個元件。
- **dnd-kit**：排序抽象套在 sheet 上，讀者得先懂它才看得懂手勢。
- **只讓 Pixel Pet 導覽可拖**：表單類 sheet 全部退回規格外，等於放棄「同一元件同一行為」。

## Revisit When

第二個需要自由拖曳與慣性的表面出現（例如可調整高度的面板），或瀏覽器原生支援足以取代自寫手勢時。
