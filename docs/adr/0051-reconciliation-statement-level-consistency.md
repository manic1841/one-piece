# 對帳為報表層級的科目一致性檢查，不做逐帳戶定位

**狀態：** 已接受（2026-09 修訂）
**規範來源：** [financial_report.md](../financial_report.md) §3；[CONTEXT.md](../../CONTEXT.md)（Reconciliation）

產品規格的 Account Reconciliation 階段（銀行餘額 vs 帳面餘額差異、定位問題帳戶）在資料架構上辦不到：實體帳戶與會計科目刻意分離（ADR-0007），帳面餘額無法逐帳戶計算。因此對帳的目的定義為**報表層級的科目一致性**——檢查整體科目的金額在跨報表之間是否一致，不一致時以警示提醒，不嘗試定位到單一帳戶，也不引入帳戶-科目映射。

現金科目的檢查已存在（ADR-0020）：現金流量表期末現金為分錄計算值，資產負債表現金類科目為快照實際值，差額以對帳差異提醒顯示且不自動調平；本 ADR 沿用此機制與原則。取捨是對帳結果是「整體一致 / 有差異」，不是「哪個帳戶錯了」；差異的根因仍由使用者回到原始紀錄追查。

## Considered Options

- **引入帳戶→LedgerCode 映射以計算逐帳戶帳面餘額**：違反 ADR-0007 語意分離，且超出規格 out-of-scope。拒絕。
- **對帳定義為快照＋零活動警示組合（先前版本）**：仍隱含「找出問題帳戶」的定位目標，與資料架構不符。拒絕。

## Consequences

- 2026-09 修訂：股票科目延伸檢查擱置——市值由使用者手動輸入，沒有獨立觀察來源，不構成對帳依據（見 CONTEXT.md 的 Reconciliation 條目）。對帳目前僅限現金。
- 關帳工作流不做獨立的對帳階段；財務報表本身即呈現現金一致性（階段模型見 ADR-0052）。
